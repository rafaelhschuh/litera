# Android Agent Contract

Este subprojeto herda o [AGENTS.md raiz](../AGENTS.md). Antes de alterar Android, leia o [README](README.md), [ADR-0010](../docs/decisions/ADR-0010-android-webview-host.md), [arquitetura](docs/architecture.md), [segurança](docs/security.md), [testes](docs/testing.md) e [build/release](docs/build-and-release.md), além dos contratos obrigatórios da raiz.

1. O Android é um host Kotlin do aplicativo web Litera completo em WebView de primeiro nível. Reutilizar catálogo, login, leitores EPUB/PDF, preferências e offline existentes; não criar iframe para hospedar o site, segundo backend, clientes API paralelos ou novas engines de leitura.
2. Setup do servidor e integração com janela/ciclo de vida são nativos. Não duplicar toolbars, menus ou controles que já pertencem ao app web.
3. Validar origem canônica por esquema/host/porta; rejeitar credenciais, caminhos, query e fragmento. HTTPS é padrão, HTTP exige consentimento explícito. TLS inválido nunca recebe bypass. HTTP remoto pode não oferecer secure context e offline completo.
4. Exigir AndroidX WebKit `WebViewFeature.MULTI_PROFILE` antes de carregar o servidor. Usar `WebViewCompat.setProfile` com perfil persistente por origem. Provedor sem suporte mostra orientação para atualizar Android System WebView/Chrome; nunca usar o perfil padrão como fallback silencioso.
5. Sessão, cookies, DOM storage, IndexedDB e Service Worker pertencem ao perfil WebView privado do APK. Não importar cookies do Chrome, guardar senha em preferências ou construir um segundo cookie jar. Origem/conta e logout seguem o isolamento do cliente web; backup Android permanece desabilitado.
6. Livros, metadados e URLs são entradas não confiáveis. Desabilitar acesso direto file/content, conteúdo misto e cookies de terceiros. Navegação externa sai somente com gesto e URL HTTP(S) validada; bloquear schemes arbitrários e impedir que o host carregue outra origem como Litera.
7. Comunicação web→host usa `WebViewCompat.addWebMessageListener` com allowlist exata da origem, main frame e verificação do documento de primeiro nível. Não usar `addJavascriptInterface`. Mensagens declarativas só atualizam aparência/estado da janela ou abrem os ajustes limitados do host; não recebem sessão, filesystem, execução arbitrária, intents ou rede privilegiada.
8. Progresso mantém locators e conflitos EPUB/PDF do app web e sua outbox IndexedDB. Não criar fila/progresso Kotlin paralelos. O evento `litera-host-pause` pede captura/flush pelo reader existente; não garante envio antes de process death ou com app encerrado.
9. Barras/cutout/IME seguem insets nativos e o tema efetivo do app/leitura, obtido por `theme-color` e tokens CSS existentes. Não injetar redesign do site ou cores arbitrárias. Preservar ícone adaptativo Litera, margem segura e camada monocromática.
10. Manter tela acesa somente com Activity em foreground, reader ativo e preferência local do host habilitada. Voltar respeita diálogo/fullscreen/router/histórico antes de sair. Pausa e retomada não recarregam o site nem perdem posição.
11. Erro de subrecurso não pode substituir a interface por tela de erro. Falha de rede deve preservar shell offline disponível; erro principal sem conteúdo oferece recuperação. Não anunciar offline só porque há cache HTTP: validar downloads explícitos, cold start e fila no WebView.
12. Versão deriva do package.json raiz; nunca bump Android isolado. Não versionar segredo/keystore. APK debug de CI é preview sem assinatura estável entre runners.
13. Executar gates Android e web pertinentes, distinguindo unitário, browser, emulador e aparelho físico. APK compilado não comprova UX, isolamento, offline nem restauração.
14. Mudanças em bridge, provedor WebView, storage, navegação, assinatura ou compatibilidade atualizam ADR, contratos e links na raiz. Não declarar fluxo pronto com mocks/TODOs.
15. O novo PR WebView fica em draft e sem merge até o usuário testar o APK e autorizar expressamente. O PR nativo rejeitado não é base de aprovação; CI não substitui teste e autorização do usuário.
